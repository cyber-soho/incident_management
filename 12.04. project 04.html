Live capture and BPF filtering with tcpdump

Objective: capture a few minutes of traffic on your lab interface, and learn to slice it down with BPF expressions.

1

List interfaces and pick the lab one:

ip a
sudo tcpdump -D

Note the number/name. NEVER use the production Wi-Fi.

2

Start a five-minute capture, writing to a file:

sudo tcpdump -i enp0s8 -w /tmp/labA1.pcap -G 300 -W 1

Generate traffic (web browsing, ping 1.1.1.1) in another terminal while this runs.

3

Replay the file with filters. Take a screenshot of each output:

tcpdump -r /tmp/labA1.pcap -nn 'tcp and dst port 443'
tcpdump -r /tmp/labA1.pcap -nn 'udp port 53'
tcpdump -r /tmp/labA1.pcap -nn 'not (port 53 or port 80 or port 443)'
tcpdump -r /tmp/labA1.pcap -nn 'host 10.0.2.15'

Deliverable A1

Four screenshots (one per filter) + a short paragraph explaining BPF expressions (primitives, qualifiers, boolean operators).

Same capture, opened in Wireshark

Objective: move from CLI to GUI, learn display filters, and explore Wireshark dialogs.

1

Open the file:

wireshark /tmp/labA1.pcap &
2

Apply Display Filters (Re-create Task A1):

  • tcp.dstport == 443
  • dns
  • not (tcp.port == 80 or tcp.port == 443 or udp.port == 53)
  • ip.addr == 10.0.2.15
3

Walk through menus & screenshot each:

  • Statistics → Conversations (who is talking, how much)
  • Statistics → Endpoints (every IP address)
  • Statistics → Protocol Hierarchy (bytes per protocol)
  • Statistics → I/O Graph (packets/sec over time)
  • File → Export Objects → HTTP (extract unencrypted files)
  • Right-click TCP packet → Follow → TCP Stream (compare plain HTTP vs HTTPS)

Deliverable A2

Five screenshots (one per menu) + half-page note comparing capture filters (BPF) vs display filters.

Hunting Anomalies

Objective: find traffic that does not belong using a Malware-Traffic-Analysis.net sample PCAP.

Three Anomaly Patterns

  • (a) Unusual Ports

    Look for outbound on 4444, 8080. Sort by frequency.

    tcp.dstport > 1024 and not (tcp.dstport in {443, 8443, 3389, 5060})
  • (b) High-Volume Flows

    A single IP carrying 70% of bytes. Use Statistics → Conversations, sort by bytes.

  • (c) Beaconing

    Steady drumbeat callback to C2. Filter convo, use I/O Graph (1s interval).

Simulation: I/O Graph Beacon Pattern

This dynamic chart illustrates what a C2 beacon looks like when plotted over time. Notice the highly regular, repeating spikes representing small, periodic bursts of packets sent by the infected host.

Deliverable A3

For each pattern (3 total): one annotated screenshot + short paragraph (what you saw, why benign is unlikely, next steps).

Building the incident timeline

Objective: turn your matrix into a clean chronological narrative (6-10 lines).

Timeline Rules

  • Use UTC timestamps to avoid timezone confusion.
  • One sentence, present tense, neutral tone per event.
  • State the source (PCAP, FW, IDS).
  • List IoCs (IP, domain, hash).
  • Include Analyst notes for context.

Deliverable A5

The 6-10 line timeline + one paragraph "executive summary" written above it.
