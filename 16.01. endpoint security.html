Endpoint Security: The Edge

Walking from the data-center to the edge. Phones, cameras, and PLCs are all computers, but none behave like a standard laptop. Explore the unique security challenges, expanded attack surfaces, and adapted response procedures for Mobile, IoT, and OT/ICS environments.

1. The Three Families of the Edge

Mobile, IoT, and OT devices share the same network as traditional endpoints, but require completely different defense strategies. You cannot deploy an EDR agent on a PLC or remote into a smart bulb. Explore the profiles of each family below.

2. The Flat Network Multiplier

The attack surface has exploded from 1 device per employee to up to 20. When weak edge devices exist on unsegmented networks, they become the beachhead for devastating lateral movement.

The Casino Fish-Tank (2017)

A real-world incident demonstrating why the inventory problem must be reframed around blast radius rather than mere presence of weak devices.

🐟

Internet-Connected Thermometer

Vendor placed it on corporate Wi-Fi. IT didn't know it existed. No agent, no patch.

↓

Lobby Wi-Fi → Sensor VLAN

Attacker compromises thermometer, finds routing available to internal sensor networks.

↓

Sensor VLAN → Database

Four hops across a flat network. No segmentation to stop the pivot.

💵

Objective Reached: High-Roller Database

~10 GB of sensitive records exfiltrated. The blind spot was the lesson.

Key Takeaway:

Assume the weak endpoint exists. Engineer the segmentation that makes it irrelevant. Contain the blast radius.

3. Adapting NIST 800-61

The Incident Response playbook is not thrown out for IoT and OT—it is translated. You cannot run `taskkill` on a PLC. Interaction below contrasts classic IT moves with edge-adapted moves.

Classic IT Move

  • Push an EDR agent to the host.
  • Pull a process tree directly from the machine.

Adapted Edge Move

  • Position the network to see the device (Span ports, NetFlow).
  • Correlate ambient telemetry (vendor cloud console, engineering workstation logs). The PLC's neighbor tells the story.

Classic IT Move

  • Isolate the host via EDR network quarantine.

Adapted Edge Move

  • Quarantine the path, not the device.
  • Change switch ACLs, micro-segment the conduit, drop the C2 channel at the firewall. Keep physical processes running if safe.

Classic IT Move

  • Kill malicious processes, delete registry keys.
  • Reboot and restore from backup immediately.

Adapted Edge Move

  • Reflash to a known-good vendor image (firmware is OS+App+Persistence in one blob).
  • Recovery window is governed by operations (plant turnaround schedule), not IT. Be ready when the window opens.

Lessons Learned: The Golden Rule

Fix the asset inventory first. You cannot defend what you never inventoried. The compromised device was likely not on your list.

4. Tools & Standards

Understanding the distinction between management and detection tools, and knowing which compliance standards to reference when architecting defenses.

MDM vs. EDR Overlap

Buy each capability once. Be able to tell both stories about every device.

MDM (Manage Posture)

  • • App-store policy
  • • Encryption-at-rest
  • • Remote wipe/geofence
  • • VPN/Wi-Fi profiles
  • "The phone is encrypted."

The Overlap

  • Asset inventory
  • Compliance reports
  • Log forwarding
  • Role-based admin

EDR (Detect Behavior)

  • • Process telemetry
  • • Memory scanning
  • • Network containment
  • • Live response shell
  • "Phone is calling C2 at 3am."
